What is this

Fonn is a local command line tool and a reusable TypeScript core. It wraps the CLIs you already use. Running fonn opens the unmodified Claude Code or Codex interface, with its own login, settings, permissions and questions.

On top of that launch, Fonn adds three things:

  • Saved profiles. A provider, model and effort level stored under a short name, so fonn --profile focused always starts the same way.
  • Subagent guidance. Startup instructions that ask the agent to hand meaningful independent work to its built-in subagents, while simple tasks stay with the parent.
  • Output filtering. Recognized noisy shell output, like test progress rows, is shortened before the model reads it. The full original is archived locally and can be read back in bounded slices.

Separately, fonn run starts a structured task through the Claude Agent SDK, with validated results, budgets and estimated usage accounting. That path uses an API key and API billing. See permissions and billing.

How it works

  1. Launch

    Fonn starts the native CLI with your profile's model and effort, plus per-launch hook settings. Your global Claude or Codex settings are not changed.

  2. Delegate

    With --subagents auto, startup guidance suggests at most two workers, no nested delegation and read-only exploration. These are instructions. Your policies still decide.

  3. Filter

    Each new Bash observation passes through a post-tool hook, including observations from native workers. Only recognized formats are reduced. Reasoning, history, instructions and source files are never rewritten.

  4. Recover

    A reduced observation ends with a footer naming the archived original. The agent, or you, can read it back 4,000 characters at a time, up to 20,000 per request.

Supported formats

Format adapters handle a few tools precisely, and only from a single direct command. Pipelines, compound commands, quoted arguments and wrappers skip the adapters because their origin is ambiguous. Every command, including those, gets the generic repeated-line reduction unless you choose the strict level.

CommandWhat is reducedWhat always stays
phpunit, pest, artisan testProgress rows made only of dots with a counterRows with F, E, S or other markers, failures, warnings, summary
phpstan analyseProgress bar rows, once an [OK] or [ERROR] verdict is presentError tables, notes, the verdict
tscAdjacent byte-identical diagnostics, collapsed with a countEvery distinct diagnostic and the total
pytest, python -m pytestRows made only of dots with a [ NN%] counter, and PASSED lines in -v outputRows with F, E, s or x, failures, warnings, the summary
jest, vitest, npm testPASS file lines and ✓ passing-test lines, once the runner's totals are presentFailing files, ✕, ×, skipped tests, console output, the totals
Any command, at the standard levelRuns of 3 or more identical, non-blank adjacent lines, kept once with an exact countEvery distinct line, in order
Any command, at the similar levelRuns of 4 or more adjacent lines that differ only in numbers, UUIDs or hex IDs. The first and last stayLines mentioning errors, failures, warnings, exceptions, panics or denials. Lines without words

Other unknown output and arbitrary MCP payloads pass through unchanged. Output with terminal colour codes or carriage returns is also left alone. Observations under 2,000 characters, or where the saving would be under 256 characters, are not touched.

Choose a filter level

--filter decides whether Fonn acts, only records, or stays off. --filter-level decides how far it goes.

LevelReducesUse it when
strictFormat adapters onlyYou want the narrowest change to what the model reads
standard DefaultAdapters, plus identical lines from any commandMost work. Nothing is lost except exact copies, and they are counted
similarAlso lines that differ only in numbers or IDs, keeping the first and lastLogs repeat a line with a changing counter, worker number or request ID, and those numbers do not matter
 
fonn --default-filter-level similar   # save a default level
fonn --default-filter-level           # show it
fonn --filter-level strict            # override it for one launch
fonn run "Explain the failing job" --filter-level similar

At the similar level, a changed word such as healthy becoming unhealthy breaks the run, so that line stays. Lines that mention errors, failures or warnings are never merged. fonn resume restores the level a session used. For the standalone filter, add --level similar or --level strict to the hook command.

Collapsed is not the same as reduced. Claude Code starts tool details collapsed in the terminal (press Ctrl+O to expand). That changes what you see, not what the model reads. Fonn's filter is the part that changes model input, and it makes no promise of measured token or cost savings.

Install

Pick a route. Every route needs Node 22 or later. Claude Code or Codex must already be installed and signed in on its own.

Source checkout Available now

git clone https://github.com/nord-forge/fonn.git
cd fonn
npm ci --ignore-scripts
npm run build
node packages/cli/dist/cli/main.js --help

The checkout does not install a global command. Run the built CLI against a project with --cwd:

node packages/cli/dist/cli/main.js claude --cwd /absolute/path/to/project

To type fonn instead, print an alias line from inside the checkout and add it to your shell profile, such as ~/.zshrc:

echo "alias fonn='node $PWD/packages/cli/dist/cli/main.js'"

Standalone filters Available now

Use only the filter with your existing Claude Code or Codex. You need Node 22 or later. No Fonn CLI, npm install or provider SDK is involved. From the project where you want filtering:

mkdir -p scripts/fonn-filter
for file in hook.mjs index.mjs adapters.mjs artifact-store.mjs LICENSE; do
  curl -fL "https://raw.githubusercontent.com/nord-forge/fonn/main/standalone/filtering/$file" \
    -o "scripts/fonn-filter/$file"
done
node scripts/fonn-filter/hook.mjs --help

Then give your agent this prompt. It keeps your existing hooks and permissions, and leaves Codex hook trust to you.

Read scripts/fonn-filter/*.mjs and its LICENSE. Configure this local filter for the agent I am using: merge a Bash PostToolUse hook into .claude/settings.local.json for Claude Code, or .codex/hooks.json for Codex. Use absolute, correctly quoted paths to Node, hook.mjs and this project's .fonn/filtering directory, with --provider claude or codex and --mode filter. Preserve all existing hooks, permissions and policies; change no global settings and install no CLI, npm packages or SDKs. Add .fonn/ to .gitignore if needed. Explain how to recover full originals using the footer's bounded read command. For Codex, leave the required /hooks review and trust to me; do not bypass it. Show the local changes and any manual step. Do not make model requests to test this.

Files: hook.mjs, index.mjs, adapters.mjs, artifact-store.mjs and LICENSE. The local filtering guide has complete hook examples and shows how to pin downloads to one reviewed commit.

Everyday use

These use the fonn name. In a checkout without an alias, use node packages/cli/dist/cli/main.js.

fonn                                  # open your default agent
fonn claude                           # open Claude Code
fonn codex                            # open Codex
fonn --profile claude:fable-medium    # pick a profile for this launch
fonn --default codex                  # save Codex as the default, then exit
fonn --filter observe                 # record reductions, deliver full output
fonn --filter-level similar           # also collapse lines that differ only in numbers
fonn --filter off --subagents off     # register no Fonn hooks
fonn help                             # offline help

Pass native arguments after --, for example fonn -- --resume. Flags that override the profile, hooks or permission policy are rejected.

Resume

When a session closes, Fonn prints a command such as fonn resume <launch-id>. It restores the agent, profile, project, filter mode and subagent preference. If the provider's session ID was not observed, the same command opens the provider's session picker.

Fonn never bypasses permissions or silently approves writes and shell commands. It never extracts subscription credentials. Codex asks you to review and trust new hooks in its /hooks browser before filtering or guidance runs, and Fonn leaves that step to you.

SDK dollar figures are estimates. A request can overshoot a threshold. See authentication, estimates and budgets.

FAQ

Will Fonn lower my bill?

Fonn makes no such promise. Fewer characters in an observation is not the same as fewer tokens or dollars, and real tasks vary. Use --filter observe to see what would be removed without changing anything.

Can the model miss something important?

By default, Fonn removes only lines that match strict progress patterns or exact duplicates, and it states the count. At the similar level, it also drops the middle of runs that differ only in numbers. It never does that for lines that mention errors, failures or warnings. Claude Code and Codex merge a command's stderr into the output Fonn reads, so those lines follow the same rules. The footer tells the agent how to read the full original if it needs it.

Does it edit my conversation or files?

No. It rewrites only a new tool observation as it arrives. History, reasoning, instructions and source files are left alone.

Where are originals stored?

Under ~/.local/state/fonn by default, or a --state-dir you choose. They can contain private data. Retention is manual, and they should stay out of Git.

Do subagents get filtered too?

Yes. Native workers inherit the session hooks, so their supported Bash observations go through the same filter for every model. --filter off turns it off for parent and workers.

Is there a GUI or npm package?

A desktop app is planned but not built. The workspace packages are not published to npm as a supported install route.
