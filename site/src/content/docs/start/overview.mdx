Fonn shortens noisy command output before your coding agent reads it. You install it once, add a hook to the agent you use, and keep working with `claude`, `codex`, Crush, OpenCode or a desktop app on top of them. Hooks need a source checkout until 0.2.0. Fonn is a local command line tool and a reusable TypeScript core.

It works in three layers:

- **Hooks.** `fonn hooks install --agent <agent>` adds one hook to the agent's own user settings. Every session then gets the filter, with your global settings, the project's settings and the project rules you approved. Your login, permissions and other hooks stay as they are.
- **`fonn ui`.** A local web interface to manage hooks, filters and your own rules, try them on a test bench, and review every session with the full originals.
- **Fonn's own launchers.** Optional. `fonn claude` and `fonn codex` open the native interface with saved profiles and subagent guidance. `fonn chat` is a small agent for local models. `fonn run` starts a structured task through the Claude Agent SDK with validated results, budgets and estimated usage accounting. That path uses an API key and API billing. See [permissions and billing](/configuration/permissions-and-billing/).

## How it works

<Steps>

1. **Hook.** The agent calls Fonn's hook after each shell command. Your global agent settings gain one entry, and you can remove it any time with `fonn hooks uninstall`.

2. **Filter.** Each **new Bash observation** is checked. Only recognized formats and repeated lines are reduced. Reasoning, history, instructions and source files are never rewritten.

3. **Recover.** A reduced observation ends with a footer naming the archived original. The agent, or you, can read it back 4,000 characters at a time, up to 20,000 per request.

4. **Review.** `fonn ui` lists hooked sessions with each decision and the archived originals.

</Steps>

If anything goes wrong, the hook leaves the original output alone.
