# Fonn 0.1.0

Initial CLI release of Fonn, an independent local harness for Claude Code and Codex, with structured tasks through the Claude Agent SDK.

- Run `fonn` to open the native CLI selected by your profile with an Opus or Sonnet effort profile and collapsed tool details. In Claude, Ctrl+O expands details; display collapsing does not reduce model context.
- Use native subagents proactively by default with normal permissions; opt out of delegation guidance with `--subagents off`. Session-wide filtering also handles supported subagent shell output for every model.
- Reopen native sessions with the `fonn resume` command printed on shutdown, retaining saved launch settings and using a session-picker fallback when tracking is unavailable.
- Choose the default coding agent with `fonn --default claude` or `fonn --default codex`; explicit agent commands and profiles override it for one launch.
- Select Fable 5.2 or Mythos 5.2 with namespaced built-in profiles or pinned custom short names, subject to upstream account access.
- Create and edit local model/effort profiles and choose a default with `fonn profiles`; resumed SDK tasks retain their saved profile.
- Run `fonn codex` for the native Codex CLI, retaining its login, sandbox, approval and hook-trust flow. Codex SDK tasks are not included.
- Use `fonn run` for bounded SDK tasks with structured results, explicit approvals, recoverable output artifacts and estimated usage accounting.
- Download the standalone Node filtering modules and configure local Claude/Codex hooks without installing Fonn or npm dependencies.
- Reduce recognized noisy shell output conservatively, or choose observe/off modes. Unknown formats and arbitrary MCP issue payloads remain unchanged.
- Install the CLI through the cask in this repository. The archive contains Fonn JavaScript and lockfiles; Homebrew Node installs runtime dependencies on the user's machine without lifecycle scripts.

The desktop GUI is planned and is not included. Install and authenticate ordinary Claude Code separately for interactive use. SDK task runs require an explicit API key and separate API billing. Estimated stop thresholds can be exceeded, and character reductions are not measured token or billing savings.
